# Section page-number visibility

In development on `feat/section-page-number-visibility`; GitHub acceptance and publication are pending. This extends the existing section controls with Document default, Show and Hide. Hiding affects footer fields only: pages still count and subsequent fields continue physical page numbering. It does not introduce restart values, Roman numbering, first/even-page variants or independent header number fields.

The optional `pageNumbers` attribute accepts only literal booleans. Absent fields retain document/parent inheritance and the exact legacy section shape. Sanitized HTML, saving, backups and fresh editable sharing retain explicit false. Native imports reconstruct current effective visibility; equal-to-parent explicit intent may normalize away. Older builds may ignore the field, so HTML/backups remain the full-intent transfer path.

Measured preview, native ODT masters and document-level Word footer fields use scoped visibility. ODT master cache signatures include numbering; nested ODT scopes inherit and restore their parent. Raw compatible ODT page-master changes project supported visibility while numbering restarts and complex furniture remain guarded. Word reopens supported current footer fields and refuses explicit nested numbering overrides rather than silently flattening them. Continuous editing remains continuous; changing furniture in a continuous preview section can require a page boundary.

Seven new Node cases cover canonical attributes/HTML, repeated native ODT/current text, nested inheritance, native Word/current fields and nested refusal, raw projection with retained restart refusal, backups/sharing/no mutation, and preview with visible 1/3 around hidden page 2. A browser case covers actual ODT/Word downloads, reopen/save/reload, preview and authoring controls across five profiles. Two independent raw-master Office cases remove only the middle page-number field, require 1/hidden/3 footer values and strict actual ODT/Word resave renders. The source control is generated in Actions without the importer/exporter under test.

All tests/builds/browser/Office/live checks run on GitHub. Storage/database/session identifiers, backup envelopes, public/private hosting identities, originals, fonts and mobile safe areas are unchanged. No universal Office or device certification is implied. See COMPATIBILITY_INVENTORY.md and GITHUB_VERIFICATION.md for remaining limits and workflow.
