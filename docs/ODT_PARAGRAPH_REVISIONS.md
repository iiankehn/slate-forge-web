# Native ODT whole-paragraph revisions — November 11, 2026

Implemented on `feat/odt-paragraph-revisions`, including the preserved writing/sharing and nested-group checkpoints. Not published. This is a bounded extension of inline revisions, not support for every structural ODF change.

## Behavior

ODT can retain top-level paragraph and heading insertions/deletions, multi-paragraph changes, supported replacements and meaningful empty paragraphs. Reopening maps complete native paragraph boundaries to existing block suggestions. Current native paragraph design, supported inline formatting, author/date/notes, recording preference, Accept/Reject, bulk decisions, Undo/Redo and ordinary saving use the existing review model. Inserted-text comments remain separate; comments attached only to deleted paragraphs are omitted, as with deleted inline text. Export guidance now describes both review modes.

Native insertion markers include the relevant paragraph boundary. Deletion definitions include a neutral leading/trailing paragraph for the unchanged anchor, so reconstruction does not join the deleted text to adjacent prose. Import distinguishes leading/trailing empty anchors by native paragraph design; styled blank paragraphs retain their position. Comment-only empty anchors use an unambiguous following paragraph rather than moving the comment across a deletion. No private original-document snapshot is used.

The complete body must consist of top-level paragraphs/headings when structural changes are exported. Nested structural/text/format suggestions inside a block, moves, tracked objects, lists, tables, sections, row/boundary revisions and general formatting changes remain refused. Whole-document replacements and independent changes without an unchanged paragraph anchor are refused; a single nonempty whole-document insertion or deletion is supported. A zero-length whole-document suggestion is refused. A leading deletion whose following anchor has an incompatible heading/type or paragraph design is refused if a safe preceding anchor is unavailable. Partial cross-paragraph ranges, nested/overlapping markers, fields and unknown objects remain explicit errors on import.

The existing maximum of 1,000 revision ranges is shared across inline and paragraph changes. Existing archive, complexity, 20 MB expanded-revision, schema/sanitization and metadata checks remain active. Unsupported imports return an error before the workspace is replaced. Storage identifiers, origins, database versions, backup envelopes and fonts are unchanged.

## Actual editor evidence

LibreOfficeDev `26.8.0.0.alpha0`, build `2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`, opened/resaved 17 corrected native fixtures using an isolated headless profile. Inputs are in `docs/fixtures/odt-paragraph-revisions/`; resaves and synthetic source/decision expectations are in `test/fixtures/odt-paragraph-revisions/`. Tests reconstruct each saved file, verify paragraph order and heading type, apply both app decision outcomes and repeat through native re-export. All 17 cases pass. A further actual resave (`odt-paragraph-design-libreoffice-resaved.odt`) verifies indentation, spacing, line height, keep/widow settings and a styled blank beside an empty anchor. All 36 corrected input content/style XML parts validate against the official OASIS ODF 1.3 core schema.

The first replacement probe failed: a deleted plain paragraph anchored in the following heading reopened as a heading. It is retained as `docs/fixtures/odt-paragraph-revisions-initial-heading-loss.odt` and `test/fixtures/odt-paragraph-revisions-initial-heading-loss.odt`. The correction prefers a preceding anchor and refuses incompatible leading anchors. This failure is not counted as acceptance evidence.

Writer renames native change IDs, can split paired replacements or merge adjacent same-author insertions, and can turn an ambiguous single-paragraph whole-document change into an inline decision. Tests verify the current saved-file decision outcomes; they do not restore missing original grouping or claim exact private hierarchy retention. Writer's interactive Accept/Reject commands were not exercised; decisions are tested in Slate Forge after actual editor resaving. This is not Microsoft Word rendering certification.
