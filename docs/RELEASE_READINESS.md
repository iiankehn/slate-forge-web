# Slate Forge release assessment

The app is an owner-private beta candidate. The latest consolidated changes and validation are recorded in [RELEASE_BATCH.md](RELEASE_BATCH.md). No application accounts, cloud documents, paid APIs or telemetry were introduced. Existing origin and storage identifiers remain compatible.

## Completed in the reliability/layout update

- One ZIP backup includes text documents, history/trash, snippets, templates, PDF originals and editable PDF changes. Legacy JSON import remains supported. Imported PDF records are validated and written as one atomic batch with new IDs. Text-only emergency export is explicit when complete export cannot proceed.
- PDF writes have revision checks that reject stale writers. Save failures retain a tab-memory draft for complete backup and show a persistent main warning. Updates block during pending PDF edits/errors. Forced closure can still lose a memory-only draft.
- Measured read-only page preview: physical A4/Letter sizes, margins, repeating headers/footers/numbers, explicit breaks, text splitting, repeated table headers, columns and landscape sections. File → Print / Save as PDF uses these measured pages. Continuous editing is the default; optional live paged editing is described below.
- Adjustable PDF field dimensions and numeric geometry/removal for created annotations/fields. Undo/redo and saved values remain supported. Imported existing field geometry is unchanged.
- Image wrapping gap controls persist through HTML/JSON/DOCX. Canvas resize hit areas are larger and Escape clears selection/tool. Pointer drawing rendering is coalesced by animation frame. Search highlights are cached on cursor movement.
- Skip to document navigation and existing menu keyboard/focus behavior remain available. Desktop menus and the mobile hamburger share one catalog.
- DOCX export keeps headings with following content, adds widow control and non-splitting table rows, fits tall images inside printable page bounds and separates footer numbers from text.

## Optional live paged editing update

View → Paged editing (or the footer view switch) adds physical page boundaries and reflows editable text as the document changes. Connected table row groups move together, preserving vertical merges; ordinary column headings repeat. Endnotes flow across pages, keeping each note intact with its number. Headers, footers and page numbers are visual furniture outside the editable document. The preference persists on this browser. Decorations do not enter saved HTML/JSON, document backups or undo history; print/export keep their existing document-based paths.

Pagination waits during IME composition and refreshes after image/font loads. It is capped at 100 pages. Mixed sections, unsupported wrapped layouts, oversized row groups/objects, oversized individual notes and oversized text lines fall back to continuous editing with an explanation. Narrow screens can use Fit page width to scale physical sheets into the editing area. Manual zoom can still require horizontal panning; Continuous editing remains the responsive writing alternative. Headings keep with the start of following content. Full paragraph widow/orphan balancing and customizable keep rules are not implemented in this editing view. The measured preview can produce different page counts.

Desktop Chrome browser checks: a long text fixture flowed to six pages, including a split paragraph and an explicit break, retaining its exact editor text. Typing on the final page and undo restored the original. A 30-row table flowed to six pages with five repeated column headers. Cell editing and undo passed. Switching to Continuous editing removed all five decoration rows, leaving the original 31 table rows. The paged preference and final document marker survived reload. A mixed-section fixture selected continuous fallback and displayed the explanation. Visual checks covered paragraph and table boundaries; see [live page flow](slate-forge-live-pages.jpg). Physical mobile keyboard/IME and assistive-technology behavior still require device QA.

## Merged tables and endnotes update

Live editing and measured preview now share the same legal table break boundaries: a break never crosses a vertically merged cell, including chained spans. Groups larger than a page use the existing continuous fallback in live editing; preview can scale the oversized group with a warning. Multi-row headings repeat only when the complete first connected group contains header cells, avoiding repetition of body data.

Endnotes remain below the document rather than at the bottom of their reference page. Live editing keeps the heading with the first note and flows later notes individually. Temporary external spacing is removed on view change, refresh or editor destruction. Measured preview repeats the Notes heading, continues list numbering and keeps one anchor per note. Oversized individual notes are scaled in preview with a warning; live editing falls back with an explanation.

Browser evidence: a combined fixture with 18 two-row merged cells, 37 original table rows and 24 notes produced 13 live pages. All merged cells and note buttons measured within their page bodies. Editing a merged cell and undo restored its exact editor text; changing a note survived reload. Switching to Continuous editing restored the original editor text and 37 table rows with no remaining gap decorations. Measured preview retained all 18 merged cells and 24 unique note anchors over 13 pages with no detected body overflow or warnings. Visual review corrected note-number alignment; see [flowing endnotes](slate-forge-paged-notes.jpg). Six additional tests cover connected spans, legal ordinary breaks, invalid span bounds, external note gaps excluded from document decorations, unique preview note anchors with continued numbering and intact merged groups in preview. Preview flow unit tests use deterministic synthetic capacity; browser measurements provide the layout evidence.

## Wrapped-image paged editing update

Top-level left/right wrapped images can now remain in paged editing. Each image and all text overlapping its float are measured as one connected group. Page-sized groups move together; overlapping floats form one group. Later blocks remain independently pageable once the float ends. The final rendered image/text group is checked against the page body; the validation re-reads the page origin after browser scroll anchoring to avoid false fallbacks during editing.

Nested wrapped images (including lists, tables and quotations), images beside tables, floats crossing an explicit break, oversized image/text groups and failed rendered-fit checks use continuous editing with a visible reason. Long paragraphs beside an image are kept intact rather than split across pages, so they can trigger fallback even when the image itself is small. This is paragraph-anchored wrapping, not arbitrary page coordinates or text on both sides of one image. Saved image attributes and export paths remain unchanged.

Desktop Chrome QA: eight alternating left/right wrapped images flowed across four pages with exact source text retained and every image within its page body. Changed an image's side, gap and width midway through the document; paged layout stayed active and undo restored right wrapping, 18 px spacing and 35% width. Typing beside the image and undo restored the source text. Continuous view removed temporary gaps, and reopening restored four paged sheets, all eight images and exact text. Oversized and nested fixtures selected continuous fallback with their final markers intact. See [paged image wrapping](slate-forge-paged-images.jpg). Six additional automated tests cover connected float grouping, bottom margins, group movement, oversize/explicit-break/table fallbacks, page-body validation and independently pageable later blocks. Physical-device dragging/IME, complex wrapping and actual print output still require target-browser QA.

## Heading continuity update

Live editing now measures consecutive headings with the first line of their following paragraph, or with the next atomic block. When that minimum group does not fit, the headings move to the next page together. Long following paragraphs can still split normally. Explicit page breaks take precedence. A heading group larger than the printable area selects continuous fallback with an explanation.

Measured preview carries trailing headings when the next paragraph cannot contribute a line, or before a table/notes fragment moves to a new page. Consecutive headings travel together. Bounded retries prevent oversized groups from looping; impossible preview groups produce a warning rather than claiming the keep rule was satisfied. DOCX already used native keep-with-next and widow control; an additional XML test verifies those fields remain present. No persisted document attributes changed.

Desktop Chrome QA: 18 heading/subheading groups and an explicit-break case produced ten live pages. All 37 ordinary heading-to-following-content comparisons shared a page using rendered glyph coordinates; two heading groups received page-gap decorations. Heading editing and undo restored exact source text. Reopening preserved the ten-page layout and text. Measured preview retained exact heading/paragraph text over ten pages, with no detected body overflow, no orphaned ordinary headings and no warnings; the explicit heading/break exception remained separate. See [headings with their text](slate-forge-kept-headings.jpg). Seven new tests cover live heading moves/chains, explicit breaks and impossible groups, native DOCX fields, preview heading chains, table/note followers and explicit preview breaks. Synthetic preview tests check flow decisions; browser checks supply rendering evidence. Actual Microsoft Word, browser printing and physical-device QA remain outstanding.

## Remembered fit-width and manual zoom update

View → Fit page width and a footer Fit toggle scale live paged sheets to the workspace's available width, including padding and scrollbars. A ResizeObserver follows design-panel and container changes, with a window-resize fallback. Fit never enlarges beyond 100%. In Continuous editing, Fit uses responsive layout at 100%. Manual slider/zoom commands disable Fit and support 10–200%; Actual size restores 100%. Toggling Fit off returns to the previous manual scale. The browser preference is stored separately from documents; unavailable storage does not block zoom. Existing print CSS restores page zoom to 1, and export metadata is unchanged.

Browser viewport simulation: an eight-image/four-page document fit inside a 390 px iframe at 43%, with workspace scroll width equal to client width (375 px) and a 341 px rendered sheet. At 768 px, Fit adapted to 85%. At 1100 px, opening the desktop design panel adjusted Fit to 95% inside the reduced workspace. Zoom in left Fit mode at 95%; the Actual size command and its 100% manual state survived reload. Fit mode also survived reload and readjusted to the narrower viewport. Switching to Continuous editing retained exact source text and responsive width. See [phone-width simulation](slate-forge-fit-phone.jpg). These are iframe responsive-layout checks, not physical-device or virtual-keyboard certification. Five new tests cover preference validation, scale bounds, responsive fitting, manual override/persistence and unavailable storage/teardown.

## Long-document page navigation update

Paged editing now has a compact current/total page button, a Go to page dialog, and View menu Previous/Next page commands. The counter follows the viewport and refreshes after pagination and zoom changes. Navigation commands are unavailable in Continuous editing. Page entry validates integer bounds; a jump changes the viewport and places the cursor near the first text on the chosen page. Endnote-only pages focus the first relevant note control instead. The requested page remains current when browser scroll limits prevent aligning a final fitted page at the top; deliberate scrolling or pointer navigation releases that target. Document switches reset the target.

Desktop Chrome QA: jumped from page 1 to 7 of a ten-page document, typed at the beginning of its visible body text and undid back to exact source content. Next page advanced to 8, Previous returned to 7, and invalid page 0 left the dialog open without moving. Page 10 remained current after jumping at both 100% and 10% manual zoom. Fit width navigation also passed. A separate 13-page table/endnote document reset navigation on open; jumping to its last page focused Edit footnote 17, with a 13 / 13 counter. See [Go to page](slate-forge-page-navigation.jpg). Five new tests cover entry validation, scaled viewport detection, scroll-clamped final targets/manual scrolling, continuous-mode hiding/reset, and safe text selection around images. Physical mobile input and assistive-technology checks remain in the device QA gates.

## Local document checks update

Tools → Document checks reviews the current text document for a missing/untitled name, blank image descriptions, empty headings, skipped heading levels, a first table row without header cells and common unfinished body-text placeholders (TODO/TBD/FIXME, Lorem ipsum, bracketed Insert/Add/Your prompts and double-brace tokens). These are suggestions, including potentially intentional findings. It does not verify facts, grammar, link destinations, print quality or complete accessibility compliance. Blank descriptions can be intentional for decorative images. Code blocks are excluded from placeholder checks, and footnote attributes/design-canvas text are outside this first body-text pass.

Results can be filtered by category and refreshed. Review actions select the exact text, focus the title, open the image-description editor or navigate to Table design. Text mapping retains correct positions across inline formatting, Unicode and note atoms; placeholder ranges do not span inline note objects. A stale-result guard reruns checks if the document changed. Reports stop at 200 suggestions with an explicit partial-scan notice. Scanning is read-only, local and independent of export. Result text is created with textContent so literal markup remains inert.

Desktop Chrome QA: a deliberately unfinished fixture produced eight findings (one image, three structure, four writing). Image filtering showed one result. Added an image description from its result, then reran to see seven findings; used Review table to add header cells and saw six findings. Selected a TBD token split across bold/plain runs, replaced exactly it, and undid to the original text with table headers retained. Image/header fixes survived reload and Run again retained the six remaining findings. Literal markup produced no image element in the results. A finished letter returned no findings. See [document checks](slate-forge-document-checks.jpg). Seven new tests cover clean content, structural locations, exact marked/Unicode/atom text ranges, code exclusions, bounded non-mutating scans, literal markup and prevention of note-object selections. Physical mobile and screen-reader QA remain outstanding.

## Boundaries that remain

- Complex-layout live pagination, arbitrary page-wide image positioning and automatic two-sided text flow are unfinished. Canvas objects stay inside their canvas block; text images use paragraph anchors.
- Page preview is capped at 200 pages/10,000 blocks. Indivisible oversize objects or merged table groups can be scaled, with warnings. Continuous sections start new preview pages. Notes remain endnotes in preview/HTML and native footnotes in DOCX. Page counts can differ by renderer/font metrics. Complex widow/orphan rules are not equivalent to Word.
- Complete ZIP backups are unencrypted. Optional encrypted recovery and legacy JSON remain text-only. PDF originals and edits save separately in workspace-scoped IndexedDB. End session removes ordinary text/PDF records and leaves any separate encrypted text recovery locked. Clearing browser data can remove all local copies.
- PDF limit: 20 MB/file, 100 pages, 40 MB saved originals/workspace. Password/XFA PDFs and existing-page-text editing are unsupported. Generated text/form appearances use standard Latin font coverage. Ink signatures are visual, not cryptographic signing. OCR is one-page English printed text; scan/correction state is transient until inserted.
- Review tracks inline text changes, not formatting/structure/object edits or native typing inside code blocks. Tracked bulk replacement refuses code blocks and unresolved revisions. Formatting cleanup preserves existing annotations. Comparison is plain text. DOCX import remains content-focused and does not rebuild native review metadata or exact layout.
- Browser tokens separate workspaces, not people. Anyone using the same profile can access ordinary saved work. No cross-device sync or live collaboration is provided.

2. An actual browser-produced printed PDF, including mixed orientation, tables, page numbers, dark-page colors and printer scaling. The print action/preparation ran; this browser did not expose a usable print UI/file result. LibreOffice PDF checks are independent evidence.
