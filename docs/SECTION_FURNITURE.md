# Distinct and cleared section header/footer text

This batch adds explicit `blankHeader` and `blankFooter` intent to the existing section model. Empty legacy text keeps its inheritance behavior. A true blank flag clears the corresponding local text canonically; source models are not mutated. Section tools offers “No header text” and “No footer text.” Page-number placement remains a document setting; clearing footer text does not turn numbering off.

Measured preview and native ODT resolve scoped text, including nested sections. Native DOCX supports document-level sections; nested blank-text sections explicitly refuse Word output instead of silently losing the clearing. Word writes explicit empty default furniture parts where needed to suppress inheritance and restores document defaults after a custom section. Native ODT handles nested cleared siblings against their actual parent scope. Number-only ODT footers no longer gain an unintended leading separator. The first cleared section does not produce a false mid-document page-break warning.

Ordinary ODT page-master changes may now carry different or empty bare plain-text furniture with common supported paper, margins and numbering. A furniture-only change is meaningful even without orientation changes. Bare text and a simple footer current-page field are bounded; styled, multiple-paragraph, alternating/first-page or complex furniture retains an explicit fallback. Mixed paper/margins/numbering, restarts, nested master assignments and native history keep their previous guards. Current native furniture remains authoritative.

Optional flags survive sanitized editable HTML, ordinary saving, workspace backups and editable sharing. Native imports reconstruct current effective text relative to the active document/parent design. HTML and workspace backups are the full-intent preservation formats. Older app builds may ignore the blank flags and inherit document text. Backup envelopes, database/session identifiers, origins, private Site, body font choices and mobile safe areas do not change. This feature controls displayed furniture; originals and backups remain intact.
