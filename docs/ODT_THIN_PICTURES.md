# Thin transformed native ODT pictures

Native ODT canvas pictures can now retain rotation, X skew and reflection when their painted frame is at least 2 canvas units thick and at least .35 mm thick on the exported page. The document's editable object still uses the existing minimum 20-unit viewport. Import reconstructs that viewport around the current native picture; source-image placement, crop, opacity and supported opaque group membership survive. Original images and documents are unchanged, and no private original is restored.

## Actual exchange and rendering

The corrected input in `docs/fixtures/odt-thin-pictures/native-input.odt` contains 16 panoramic/portrait pictures across two canvases: 20:1 and 1:20 aspect ratios, 2- and 5-unit painted thicknesses, rotated/skewed/reflected combinations, varied letterbox positions, opacity and an opaque two-picture group. LibreOfficeDev 26.8.0.0.alpha0, build `2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`, opened and resaved it. The committed resave and source model are in `test/fixtures/odt-thin-pictures/`.

All 400 sampled source points stay within the full-width test’s .3-unit tolerance: maximum Euclidean distance .06434 on fresh reopening and .22071 after Writer resaving. Both original PNG assets remain byte-identical, all 16 objects remain editable, and another native export/reopen retains placement and opacity. Three additional fresh export/reopen cycles also pass.

An independent control pads each original image into a transparent square at its original pixel resolution. Its native frame stays at the original full viewport size, avoiding the new thin-frame path. Writer rendered both two-page documents to PDF. At 144 DPI, all nonwhite ink in either render lies within two pixels of the other render. Maximum RGB channel differences are 145/147, with means .04893/.03852, reflecting rasterization differences; these renders are **not pixel-identical**. Input/control ODTs, PDFs and exact metrics are retained alongside the input. Eight generated content/styles XML parts validate against core ODF 1.3. This is bounded headless Writer evidence, not universal Office or physical-device certification.

## Retained failure and limits

The initial one-unit-thick transformed corpus reopened after a provisional zoom-rounding adjustment, but its independent render lost visible ink. That adjustment was removed. The failed input, Writer resave and PDF remain as `failed-one-unit-*` fixtures. A further three-column control showed that a 2-unit frame can shrink below the safe physical size: native output lost all visible ink while its padded control retained 18 pixels at 144 DPI. The `failed-narrow-*` inputs, resave and PDFs preserve that failure. The final guard therefore requires both 2 canvas units and .35 mm at the current page scale. Native export and import refuse transformed painted frames below either floor; ordinary untransformed thin-picture behavior remains available. Do not relax this floor based on metadata reopening alone.

The minimum-size exception belongs only to painted picture frames. Ordinary shapes and editable object viewports keep their existing minimum, and transformed corners, canvas bounds, native image/archive budgets, crop/zoom limits and complexity checks remain enforced. Current external geometry, mirroring, opacity and image bytes are read instead of stale source state. Broader picture effects, unsupported formats, paint/layout and native history cases remain explicit in [COMPATIBILITY_INVENTORY.md](COMPATIBILITY_INVENTORY.md).

A supported three-column picture has a maximum sampled source-point distance .52804 canvas unit after Writer resaving, within the established native .7-unit tolerance for scaled exchange. Its native/control renders contain 184/194 nonwhite pixels and have no unmatched ink beyond one pixel at 144 DPI. The input, resave, original source and control are retained as `three-column-*` fixtures.

Canvas-first sections now accept their own empty mode bookmark beside the native group. The bookmark must have only its expected name attribute and match an enclosing `ForgeSection` name. The section importer still consumes that page/continuous intent; arbitrary destinations, extra attributes, child/text content and visible neighboring content remain refused.

## Review and verification

Six new Node cases cover 16-picture source-point preservation, repeated export/import, the actual Writer resave and original bytes, retained one-unit failures, ordinary-shape and canvas bounds, hostile dimension edits, current external picture changes, page-scale bounds, the three-column resave and strict section-mode bookmark handling. A five-profile browser scenario downloads and reopens the native file as a new document, saves/reloads it, and checks picture source points, bytes, opacity and group state through HTML output, plus a three-column native download/reopen.

Focused source review uses the installed Cloudflare `security-audit` guidance while remaining solo. The changed dimensional exception is a trusted call-site constant; native imports enforce both their logical and physical picture floors and the empty/matching section marker whitelist, and the existing numeric, image, archive and transform guards remain. No executable-markup or authorization path is added. The final functional tests and editor/fixture processing run in an offline OS namespace with an allowlisted environment, read-only source/toolchains, bounded scratch storage and process/resource limits. This is a focused source review, not the skill's full multi-agent audit.
