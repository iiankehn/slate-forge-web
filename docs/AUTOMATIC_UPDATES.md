# Silent app updates

The 2026-11-03 follow-on implements automatic updates without an Update button, update confirmation or user preference to configure. The app remains a static GitHub Pages/PWA deployment at https://slate-web.iiankehn.com/ . Storage identifiers, document/backup formats and the separate private Site remain unchanged.

Online launches register the service worker with HTTP-cache bypass and explicitly check for updates before opening the workspace. A release activates after its packaged assets download successfully. Compatible open tabs checkpoint and flush device/recovery saves before reloading once; reported save failures, pending tool work, composition, dialogs and offline preparation defer a reload and retry automatically. Returning online, restoring a suspended page or focusing the app checks again. The title field stays disabled until workspace initialization completes.

An unreachable update server must not lock users out of local writing: the startup check is bounded to 12 seconds, then permits the cached release while an in-flight check can finish. Offline use cannot download a newer release. The previous scoped cache and its hashed chunks remain available during a transition; older scoped generations and legacy caches are cleaned without touching documents, other app scopes or unrelated caches.

For the initial rollout, an already-running pre-updater tab keeps its existing JavaScript until its next navigation. The newly downloaded worker activates without the old Update action, so a subsequent normal visit adopts the new updater. Legacy tabs are not forcibly navigated over in-flight work. After the updater is loaded, controller changes also trigger guarded automatic reloads in compatible tabs. Optional diagnostic checking remains in App status; it is not required for updates.

Unit cases cover waiting activation, pending/failed saves, cross-tab controller replacement, first-install loop prevention, unreachable checks, reconnection and suspended-page recovery. Worker cases cover failed installation, automatic activation, scoped cache retention and old hashed modules. Browser cases perform a real release A→B upgrade with two saved workspaces, check both retain their writing, then reopen B offline on desktop Chromium/Firefox/WebKit and phone Chromium/WebKit emulation. Live primary files, shell chunks and service-worker code/manifest/cache digest are verified.

These checks do not certify physical devices, operating-system installation behavior, every browser lifecycle or actual storage eviction. A cached installation must receive the new release before its new updater can run. Browser/network/CDN failure and save failures take precedence over a promise of an instantaneous latest version; local work remains usable and updates retry without an update prompt.
