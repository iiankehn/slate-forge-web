## Build

Run `npm ci`, `npm run build`, and `npm test`. Serve `dist/` over HTTPS. Dependencies are pinned in package-lock.json and bundled without a CDN. Build generates third-party notices and a versioned service worker.

Editor: Tiptap/ProseMirror. DOCX export: docx. DOCX content import: Mammoth. HTML sanitization: DOMPurify with a restricted formatting and URL policy. Archive preflight: fflate. Build: esbuild. Tests use Node, jsdom and fake-indexeddb.

## Editing and design

Rich text, headings, selected fonts/sizes, colors/highlighting, links, lists, embedded images with accessibility descriptions, contextual tables, paragraph spacing/indentation, find/replace, document outline, statistics/writing goals, focus mode, templates, duplication, Recently Deleted and version history.

Document styles Forge, Editorial and Classic coordinate body fonts and heading typography. Reports, letters, proposals and creative briefs create separate editable documents. Explicit text formatting overrides document defaults. Page settings include A4/Letter, orientation, margins, headers/footers and page breaks.

View → Paged editing adds editable page boundaries, automatic line flow, headings kept with following content, whole table row groups (including vertically merged cells), repeated table headings, flowing endnotes and page-sized wrapped-image groups and long paragraphs whose full-width tails continue after the float ends. Continuous editing remains the default; the view preference persists on this browser. Live pagination is capped at 100 pages and falls back to continuous editing for mixed sections, nested wrapped images, wrapped images beside tables or crossing explicit breaks, and oversized objects, wrapped text groups, row groups or individual notes. View → Fit page width or the footer Fit button scales paged sheets to the available editing area and follows window/panel changes. The fit/manual view preference and manual 10–200% zoom persist on this browser. Fit never enlarges beyond 100%; Continuous editing uses responsive width at 100% while Fit is selected. Manual zoom can require horizontal scrolling. These are screen settings and do not alter document or export sizes. Paged editing also shows a current-page counter; click it or use View → Go to page, Previous page or Next page. A jump places the cursor on the chosen text page, or focuses a note control on an endnote-only page. Navigation is unavailable in Continuous editing. Temporary page decorations are excluded from saved content and undo history. View → Page preview and File → Print / Save as PDF provide measured output pages with repeating headers/footers, page numbers, text splitting, table-header repetition and section orientation. Preview remains read-only and may differ from the editing page count. Use the app print action, 100% browser print scale and disable browser-added headers/footers. Plain HTML remains continuous. DOCX retains native sections and page fields.

Interface appearance offers White, Colored, Grey, Dark and System. Theme, custom accent color and dark-page viewing preferences are saved in localStorage separately from documents. The accent works across all themes; very light/dark choices adapt for readable controls. System follows the OS light/dark setting. An optional dark page follows Dark or System-dark mode. It uses screen-only color adaptation and compensates images to retain their colors. Printing and exported files retain original document colors; this viewing preference is never written into document content/layout.

Images support continuous 15–100% width, alignment, left/right text wrapping and a 0–48 px text-flow gap, retained in HTML/JSON/DOCX. Drag an image near a paragraph's left/right edge to anchor it there; a center drop removes wrapping. Move-earlier/later buttons provide an alternative to dragging. Wrapped images need space for text; narrow the image when necessary. This is paragraph-anchored flow, not arbitrary page x/y positioning or text wrapping on both sides. HTML/JSON preserve wrapping; DOCX exports square-wrapped paragraph anchors. Rendering varies between DOCX applications.

Tables support grid, striped and minimal styles; sage/ink/warm palettes; cell padding; header toggles; and merge/split commands. Merge/split require a suitable cell selection. Shared normalized style rules drive editor/HTML output and DOCX formatting.

## Files

The Open dialog accepts DOCX, HTML, text, complete workspace ZIP backups and legacy JSON backups through a native file input. Files are read on the device. DOCX/text imports are limited to 5 MB, HTML to 20 MB JSON backups to 50 MB and ZIP backups to 120 MB. ZIP preflight caps expansion at 120 MB and 205 entries, with 50 MB text content and 40 MB PDF originals. DOCX preflight rejects missing core parts, over 1000 entries, an expanded entry over 20 MB or total over 30 MB. This is defensive preflight, not a malware scanner. Image pickers accept supported source photos up to 1 GB and optimize large images locally before embedding; the stored data URL is bounded to 1.5 million characters. HEIC/HEIF requires browser decoding support.

DOCX import is content-focused; complex layout, wrapping, headers/footers, comments, tracked revisions and typography may change. Export supports common formatting, paragraph settings, lists, links, embedded raster images, tables, page breaks and page settings. Images are converted to PNG for DOCX. HTML preserves normalized page metadata and does not reimport page furniture as body content.

Exports prepare an explicit Save link, with native Share/Save to Files where supported. The default ZIP backup contains documents, trash, snippets, custom templates, version snapshots, PDF originals and editable PDF annotation/form state. Legacy JSON backups remain readable. PDF records restore atomically with new identifiers after document/PDF validation. A text-only emergency JSON export is available if complete backup cannot be created; its PDF exclusion is explicit. Exports remain on the device after End session.

## Sessions and device recovery

The working workspace, including documents, history and trash, saves automatically in plaintext IndexedDB (document-studio-device), independently of encrypted recovery. A plaintext sessionStorage snapshot under document-studio.session.v1 provides tab continuity. Closing and reopening restores the most recently saved workspace; Device storage lists other saved workspaces. Opening a workspace that responds as active in another tab is blocked. Revision checks reject stale writes even when the live-tab probe fails. Live duplicated tabs use a BroadcastChannel probe to start empty when another active tab responds with the same random workspace identifier. This is best-effort workspace separation, not authentication. Suspended/restored tabs may retain copies, and anyone using this browser profile can open ordinary device-saved work. Device saving is browser-profile storage, not per-user authorization.

Device recovery is optional and requires HTTPS, Web Crypto and IndexedDB. Enable it from Device recovery and save the generated recovery code privately. Workspace copies are AES-256-GCM encrypted with a fresh nonce per save; the code/key is held only in memory and is not saved automatically. IndexedDB stores encrypted content, an opaque identifier, revision and timestamp. No documents or recovery codes are uploaded to a backend. Anyone with the code and access to this browser profile can unlock the copy. A lost code cannot be reset.

Recovery saves are debounced, serialized and revision-checked to prevent silent concurrent overwrites. Save failures show a persistent warning. Save recovery now explicitly flushes the latest state. Visibility/page-exit events attempt a save, but shutdown saves cannot be guaranteed; wait for saved status or export a backup before leaving. On reload, enter the code to unlock recovery while retaining the tab's latest work. Replacing a workspace with the saved copy requires an explicit checkbox.

Recovery is limited to the original browser/profile. Browser clearing, private browsing, quota limits and eviction can remove data. The independent Device storage dialog can request persistent storage, with recovery either on or off; browser approval is not guaranteed and does not prevent manual clearing. Keep exported backups and the recovery code separately. Device recovery is not cloud sync or a substitute for independent backups.

End session first attempts to save active recovery, drains pending ordinary device writes, removes the ordinary workspace content, then clears tab documents, trash, undo history, inspectors and generated file links, and discards the recovery key. An opaque ended-workspace tombstone blocks suspended writers from recreating the removed copy. Other saved workspaces and appearance settings remain. The encrypted device copy remains locked for later recovery. On save failure, the UI offers backup or explicitly ending without the latest save. Storage removal failures are reported. Browser restoration and downloaded exports are outside the app's control; this is not forensic erasure. Shared-device users must end their session.

Session storage failures preserve the last saved record and show an export warning. Up to 30 active documents are supported; browser storage can fill sooner, especially with images/history.

## PWA

The manifest provides standalone installation, local icons, and New/Open/Saved workspaces launch shortcuts. On compatible installed desktop browsers, DOCX/HTML/text files can open through the OS file-handler interface; these use the same import checks as manual files. Pending launches stop when the workspace changes. Feature availability varies by browser/platform; ordinary file inputs remain available. On HTTPS, a service worker caches only versioned application-shell assets. It excludes document/API requests and sign-in screens; an online sign-in response is honored rather than bypassed by cache. Offline access requires a previously successful shell cache and may depend on hosting/browser behavior. UI reports availability instead of promising it before installation succeeds.

Updates wait for the Update app action, checkpoint and flush device/recovery saves before activation, reject updates while save problems remain, and reload into a consistent version. App status offers manual update checks, storage estimates, persistence status, mode and offline readiness. A header status button stays available beside the document title. Updates are available from Tools → Update app. Browser online/offline signals do not guarantee network reachability. The shell caches third-party notices too, and a noncached offline navigation returns setup guidance rather than a generic browser failure. Installing/opening in a different browser or device may use different storage; export before switching. Install affordances and platform instructions are feature-detected.

## Design canvas foundation

Design canvas is an editable block within the flowing document. Add text boxes, rectangles, ellipses, lines and arrows; position and resize them by pointer or numeric controls, rotate, set fill/stroke/opacity and typography, and adjust the canvas background/height. Multi-selection supports alignment, grouping/ungrouping, duplication, lock/hide and front/back layer ordering. The layer list can select obscured, hidden or locked objects. Grid/center guides and optional move snapping aid placement. Arrow keys nudge by 1 design unit (Shift: 10), with local undo/redo. Text uses bounded plain text with approximate line wrapping; overflow clips to its frame. Objects rotate around their unrotated frame and may clip at canvas boundaries.

Changes commit to the document and its normal device/session saves automatically, including local undo/redo actions. Save status and an export-backup action appear in the designer when storage needs attention. Closing during an unfinished drag discards that unfinished movement; completed edits are retained. Pending PNG exports are discarded if their editor closes. Existing document history, trash, duplication, backups and encrypted recovery carry the scene in node attributes.

JSON and exported HTML retain normalized editable scene data. HTML includes a generated, self-contained SVG preview; import strips arbitrary SVG markup and rebuilds the preview from allowlisted scene data. Canvas limits: 100 objects, 2000 text characters per object, fixed 900-unit logical width and 240–1400-unit height. Colors, fonts, IDs and geometry are constrained, and generated SVG escapes text without supporting scripts, links, foreign objects or external resources. Hidden layers remain in editable scene data; hiding is not redaction.

Standalone SVG and 2× PNG exports are available. DOCX exports flatten each design canvas to a PNG, preserve its aspect ratio and fit it within available page dimensions. Missing canvas raster data fails export rather than silently omitting the canvas. DOCX reimport yields an ordinary image, not editable design objects. Browser print renders the SVG without editing controls or guides, but completed printed output remains a real-browser release check.

Browser QA verified numeric geometry/typography, grouping/duplication/undo, locks, grouped keyboard movement, real pointer dragging with snapping, corner resizing, saved scenes after reload, PNG preparation and DOCX preparation with the scene included. Automated tests cover normalized imports/ID collisions, escaped SVG, group bounds/locks, alignment/order, sanitized editable HTML round trips, document undo/serialization, designer controls and DOCX image inclusion. Completed downloads and real touch/stylus devices remain unverified.

This is a canvas-block foundation: objects can move freely inside the canvas, while surrounding document text flows above/below the whole block. It does not place objects over arbitrary document text or wrap text around canvas shapes. Canvas images/cropping, drawing and PDF/forms/OCR tools are described below.

## Design, PDF, OCR and review tools

The design canvas also supports embedded raster images with replacement, crop anchors/zoom/fit, flip, proportional frames, rotation, pen/highlighter strokes and whole-stroke erasing. Flyer, worksheet and newsletter templates are editable starting points. Canvas objects have independent geometry but do not drive surrounding paragraph text flow. PDF & forms opens ordinary PDFs, fills AcroForms, adds text/checks/highlights/ink, reorders/rotates pages and creates editable text/checkbox/dropdown fields. Choose a local TTF/OTF font under 10 MB for international annotation and form appearances; missing glyphs stop export. Font data stays with edits and complete backups. AES-256 export protects a separate downloaded copy with a password that is never saved. Password-protected inputs require an explicit choice before an unlocked editable copy is saved in ordinary device storage. A local RSA PKCS#12 certificate can sign a final exported PDF with SHA-256; certificate/password are not saved. Recipient readers determine certificate trust; no trusted timestamp/revocation/LTV is supplied. Signed inputs remain view/export-only to preserve their signature bytes. XFA and editing existing page text remain unsupported. Limits remain 20 MB/input, 100 pages and 40 MB saved PDF originals/workspace. PDFs and edits are workspace scoped, removed by End session, and included in complete ZIP backups and encrypted recovery. Legacy JSON excludes PDFs. Ink signatures are drawings.

Scan & OCR recognizes printed text locally using bundled Tesseract models for English, Arabic, simplified Chinese, French, German, Italian, Japanese, Portuguese, Russian and Spanish. Select a scan language and optionally include English. Choose an image/camera scan or PDF page/range, crop/rotate/straighten, recognize, correct and create a document. Source scans, corrections, language and page-range settings persist by workspace and are included in complete backups/recovery. End session removes them. Language models are served from this app's origin and cached on demand; Offline preparation downloads all PDF/OCR components. Review accuracy, especially mixed scripts, vertical text and camera scans. Shell-ready status alone does not certify tool availability.

Review tracks local text, supported formatting, and grouped structural/object edits, with individual/bulk decisions and Undo. Structural replacements retain deleted/inserted top-level block copies; deleted copies are protected, and later edits to the inserted copy remain in that group. Tables, canvases, images, block insertions/deletions/moves and paragraph/heading/code conversions retain their original content for rejection. Changes spanning an existing group must be decided before combining them; tracking-off cannot strip pending metadata. Changes beyond 10,000 nodes or 10 MB per changed snapshot are refused rather than silently becoming direct edits. HTML/device backups retain block review; DOCX/ODT require those decisions first. Comparison includes text, formatting, object, structure, moves and page-design reports. Column sections carry orientation and headers/footers to DOCX; mixed sections still use continuous editing. Productivity adds Ctrl/Command K search, tags, snippets, saved document templates and heading-color overrides.

## Reliability and layout update

PDF writes use optimistic revision checks, preserving the last successful record when another writer has changed it. A save failure keeps a tab-memory draft available to complete backup, even after closing the PDF tool. The main save warning persists until outstanding drafts save successfully. These drafts cannot survive a forced tab close; export first. Updates are blocked while PDF edits or save errors remain. Standard browser/profile storage limits still apply.

PDF-created fields and annotations expose numeric position/size controls; new fields have adjustable dimensions. Geometry edits and removal participate in PDF undo/redo. Imported pre-existing field geometry remains unchanged. Canvas resize hit areas are enlarged, Escape clears canvas tool/selection, pointer drawing renders at most once per animation frame, and search decorations are reused during cursor-only transactions. A Skip to document link improves keyboard access.

The page preview uses physical A4/Letter dimensions and margins. It splits long text while preserving inline marks, repeats table headers, starts explicit breaks/sections, and handles landscape/columns. Oversized indivisible objects/merged-row tables may be scaled with a visible warning. Continuous sections start a new preview page; DOCX preserves continuous sections. Preview footnotes remain endnotes. Preview is limited to 200 pages/10,000 blocks and may differ from a Word-compatible renderer; font metrics and printer settings affect output. Print preparation and cleanup are exercised, but an actual browser-produced PDF file remains unverified in the cloud browser.

It retained 65 unique table-row markers, image media, native comments, insertions/deletions, footnotes, columns and a final marker. This is not Microsoft Word certification.
